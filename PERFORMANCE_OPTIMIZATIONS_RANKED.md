# Kip Performance Optimizations, Ranked by Return on Effort

This is one ordered backlog, ranked primarily by expected performance benefit divided by implementation effort. It also accounts for confidence: a small, well-evidenced improvement ranks above a theoretically larger but speculative rewrite. Benefit is relative to the workload named in each entry; closely coupled ideas from `PERFORMANCE.md` and the broader audit are consolidated into implementable changes.

1. **Prevent test-suite CPU oversubscription** — **Benefit: very high; effort: very low.** Tasty currently uses one worker per processor while every spawned `kip` defaults to `-N4`; run test subprocesses with `+RTS -N1` or cap Tasty workers to `processors / capabilitiesPerKip`.
2. **Remove `cachedEval` from ordinary module caches** — **Benefit: high; effort: low.** Normal cache loads replay `cachedTypedStmts` and do not restore the serialized evaluator snapshot; retain evaluator snapshots only in the prelude image and bump the cache version.
3. **Eliminate the successful-parse repeated-binder source rescan** — **Benefit: medium; effort: low.** Detect repeated binders structurally while parsing patterns instead of scanning every successfully parsed file again with `findRepeatedPatternBinderText`.
4. **Add a no-comment fast path to `removeComments`** — **Benefit: medium; effort: very low.** Return the original `Text` immediately when `"(*"` is absent, which should cover most files.
5. **Stable-deduplicate missing Foma batch inputs** — **Benefit: medium; effort: low.** Ensure each absent surface/stem is sent across the FFI only once in parser and renderer `upsCachedBatch`/`downsCachedBatch` calls.
6. **Debounce and cancel stale LSP analysis** — **Benefit: very high for editor latency; effort: medium.** Analyze in versioned workers, cancel the prior worker after a new edit, and implement request cancellation instead of finishing work that will be discarded.
7. **Add typechecker output modes** — **Benefit: high; effort: medium.** Runtime mode should omit resolved names, types, and locations; codegen mode should retain call targets; LSP mode should collect everything.
8. **Maintain parser membership and arity indexes incrementally** — **Benefit: high; effort: medium.** Replace repeated `Set.fromList`, `Map.fromList`, `elem`, and association-list lookups for constructors, type parameters, primitive types, and type constructors with state-resident indexes.
9. **Use structural LSP span/range keys** — **Benefit: medium; effort: low.** Replace `T.pack . show` hash keys with compact offsets or proper `Hashable` instances for spans and ranges.
10. **Use queue-based codegen reachability traversal** — **Benefit: medium; effort: low.** Replace `rs ++ newRefs`, `accRefs ++ refs`, and recursive reference-list concatenation with `Seq` or reverse accumulators.
11. **Group tagged statements and definitions once for `js-modules`** — **Benefit: medium; effort: low.** Build `Map FilePath [Stmt]` and definition sets once instead of repeatedly filtering all statements and using `notElem` for every module.
12. **Mark the LSP workspace definition index complete and cache misses** — **Benefit: medium; effort: low.** Prevent an unresolved symbol from triggering another full workspace scan after indexing has already completed.
13. **Use Cabal's real `split-sections: true` setting** — **Benefit: low-to-medium startup/build size; effort: very low.** The current `-split-sections` GHC option is a no-op on Darwin; verify binary-size and launch-time changes after switching.
14. **Skip writes for unchanged generated JavaScript modules** — **Benefit: medium for incremental builds; effort: low.** Compare an input/output digest before rewriting every `.mjs` file.
15. **Pass type-constructor maps directly through the typechecker** — **Benefit: medium; effort: low-to-medium.** Remove remaining `Map.toList tcTyCons` conversions from normalization and unification paths.
16. **Combine pattern normalization/type/span traversals** — **Benefit: medium; effort: medium.** Have one pattern traversal return the normalized pattern, bindings, and resolved span/type pairs instead of calling `inferPatTypes` and `inferPatTypesWithSpans` separately.
17. **Cache rendered identifiers and type signatures at a higher level** — **Benefit: medium; effort: low-to-medium.** Cache `(Identifier, cases)` and normalized type/signature renderings, not only their underlying Foma calls.
18. **Make spelling suggestions lazy and cache their results** — **Benefit: medium on error-heavy/LSP workloads; effort: low-to-medium.** Do not generate edit-distance candidates until a diagnostic actually needs suggestions, and cache positive and negative outcomes.
19. **Store per-module state deltas instead of cumulative snapshots** — **Benefit: very high; effort: high.** Current `.iz` files can be hundreds of times larger than their source because they contain cumulative parser/typechecker/evaluator state; store only declarations introduced by the module.
20. **Stop storing both complete parsed and typed ASTs in every cache** — **Benefit: high; effort: medium-to-high.** Use one typed syntax representation where possible or independently decodable raw/typed sections for their respective consumers.
21. **Create a lightweight LSP symbol-cache section** — **Benefit: high for workspace indexing; effort: medium.** Store exported names, signatures, and definition locations separately so indexing does not decode full AST and compiler state payloads.
22. **Add a single prelude/workspace validation manifest** — **Benefit: medium-to-high startup; effort: medium.** Validate one combined manifest/root fingerprint instead of repeatedly statting and canonicalizing the same standard-library files.
23. **Merge cached derived indexes incrementally** — **Benefit: medium-to-high; effort: medium.** Apply signature, arity, return-type, and constructor deltas rather than rebuilding whole typechecker indexes after every cached module.
24. **Add a cache string table and intern repeated identifiers on disk** — **Benefit: high cache size/decode; effort: medium-to-high.** Encode repeated names, paths, namespaces, and type components once and reference them by integer ID.
25. **Compact spans to file IDs and source offsets** — **Benefit: high memory/cache size; effort: medium-to-high.** Replace two full `SourcePos` values and a repeated optional path per node with `(fileId,startOffset,endOffset)`.
26. **Split cache-v2 into independently decodable consumer sections** — **Benefit: high; effort: high.** Separate metadata, runtime Core, codegen resolution, LSP data, and optional morphology so each command decodes only what it uses.
27. **Use hand-written, versioned cache encodings** — **Benefit: high; effort: high.** Replace generic `Binary` layouts for large AST/state payloads with fixed tags, strict lengths, compact integers, and explicit compatibility checks.
28. **Avoid reading an existing full cache merely to compare bytes** — **Benefit: medium on rebuilds; effort: low-to-medium.** Store a payload digest or trust the already-detected input change, then write atomically through a temporary file and rename.
29. **Make cache dependency validation content-addressed/Merkle-based** — **Benefit: medium-to-high startup/build; effort: medium-to-high.** Key artifacts by compiler/options/source/dependency-root digests and validate transitive dependencies through one root.
30. **Decode selected cache sections directly from strict or mapped buffers** — **Benefit: medium-to-high; effort: medium-to-high.** Avoid reading, wrapping, and fully decoding an artifact when only metadata or symbols are needed.
31. **Track per-module morphology-cache inserts at the insertion sites** — **Benefit: medium; effort: medium.** Implement the O(1)-per-genuine-miss side channel described in `PERFORMANCE.md`; never retry the rejected whole-table before/after diff.
32. **Unify parser and renderer morphology-cache wrappers** — **Benefit: medium maintenance and allocation; effort: medium.** One implementation prevents duplicate cache logic and makes insertion tracking, deduplication, and bounds consistent.
33. **Convert the rendering pipeline from `String` to `Text`/`Text.Builder`** — **Benefit: medium; effort: medium.** Remove pervasive `pack`/`unpack`, `++`, `unwords`, and intermediate `String` allocation.
34. **Batch sibling rendering morphology requests** — **Benefit: medium; effort: medium.** Replace sequential `mapM downsCached` calls where the complete set of analyses is known in advance.
35. **Optimize edit-distance candidate construction** — **Benefit: medium on diagnostics; effort: medium.** Unpack once or use a builder, test deletions/transpositions first, and avoid repeated `Text.take`/`drop`/`index` allocation.
36. **Pre-scan unique lexical words and batch morphology before parsing** — **Benefit: high parser throughput; effort: high.** Turn most morphology effects inside Megaparsec into pure lookups over one per-file analysis table.
37. **Introduce a tokenization phase** — **Benefit: high parsing/LSP; effort: high.** Tokenize comments, whitespace, words, punctuation, and spans once to reduce character-level backtracking and repeated lexical work.
38. **Index constructors by result type for exhaustiveness checking** — **Benefit: medium-to-high; effort: medium.** Avoid scanning and unifying every known constructor in each `ctorsForType` call.
39. **Memoize exhaustiveness matrix subproblems** — **Benefit: high on pattern-heavy programs; effort: medium-to-high.** Cache `isUseful`/`missingVectors` states and instantiated constructor sets to limit exponential repetition.
40. **Precompute compact overload descriptors and indexes** — **Benefit: high; effort: medium-to-high.** Index by symbol, arity, grammatical-case vector, and normalized type heads instead of repeatedly filtering and normalizing signature lists.
41. **Give AST nodes stable integer IDs and enable sound inference memoization** — **Benefit: high; effort: medium-to-high.** Key the existing memo infrastructure by node ID plus environment token instead of span/text values and avoid `NoSpan` collisions.
42. **Introduce annotation-free normalized Core types** — **Benefit: high; effort: high.** Remove spans and surface annotations from hot equality, normalization, unification, and signature-map operations.
43. **Intern/hash-cons normalized types and signatures** — **Benefit: high; effort: high.** Make common equality and map keys integer comparisons and normalize declaration signatures only once.
44. **Add fast paths before union-find unification** — **Benefit: medium; effort: medium.** Handle identical interned types, fully concrete structural equality, and simple one-variable bindings without allocating full mutable unifier state.
45. **Replace linear scoped-variable lookup with indexed scope frames** — **Benefit: medium-to-high; effort: medium-to-high.** Keep a current binding map plus a shadow stack rather than scanning `tcVarTys` and rebuilding bound-name lists.
46. **Use `IntSet` and compact grammatical-case masks** — **Benefit: low-to-medium; effort: low-to-medium.** Replace arity lists and temporary `Set Case`/`Map Case` structures with small integer sets and bit masks.
47. **Store types/constant summaries instead of full expressions in `tcVals`** — **Benefit: medium memory/cache; effort: medium-to-high.** Retain a full expression only when type inference or constant folding genuinely requires it.
48. **Record the chosen overload and argument permutation in typed Core** — **Benefit: very high interpreter performance; effort: high.** Remove evaluator-side `inferType`, signature normalization, unification, and overload search from every call.
49. **Use authoritative typed call targets in JavaScript generation** — **Benefit: high codegen; effort: medium after typed Core exists.** Delete fallback scans over all function and primitive signatures at unresolved call sites.
50. **Index codegen call targets until typed Core is available** — **Benefit: medium; effort: medium.** Add exact-name, root-name, and arity indexes instead of `Map.toList` scans in `callTargetsForIdent`.
51. **Track required JavaScript runtime primitives structurally** — **Benefit: medium-to-high codegen; effort: medium.** Accumulate runtime-symbol dependencies during generation and emit selected snippets directly instead of repeatedly scanning generated text and applying `Text.replace`.
52. **Generate JavaScript through a builder/pretty document** — **Benefit: medium; effort: medium-to-high.** Avoid constructing a giant `Text` and then running several whole-output formatting passes.
53. **Cache `Identifier -> JS identifier` and use a reserved-word set** — **Benefit: low-to-medium; effort: low.** Avoid repeated namespace joining, filtering, sanitization, and linear reserved-word lookup.
54. **Generate synchronous JavaScript for pure functions** — **Benefit: very high JS runtime; effort: high.** Use effect information to reserve `async`, promises, `await`, and async IIFEs for genuinely effectful call chains.
55. **Compile JavaScript pattern clauses into decision trees** — **Benefit: high on pattern-heavy JS; effort: high.** Share constructor-tag, arity, and field tests across clauses instead of emitting independent repeated conditions.
56. **Use compact numeric constructor tags in generated JavaScript** — **Benefit: medium-to-high; effort: medium-to-high.** Replace repeated string tag comparisons and verbose constructor objects with IDs and compact field arrays.
57. **Introduce a dedicated runtime `Value` type** — **Benefit: very high interpreter throughput/memory; effort: very high.** Stop using source `Exp Ann` nodes as integers, constructors, collections, closures, and evaluated values.
58. **Intern source identifiers into `SymbolId`s** — **Benefit: very high; effort: high.** Replace repeated `[Text]` hashing/comparison and multi-map probes with integer-keyed tables while retaining textual names only for diagnostics and serialization boundaries.
59. **Erase spans, candidates, ascriptions, and source types before evaluation** — **Benefit: high; effort: high.** Evaluate compact typed Core rather than retaining parser-oriented metadata in every runtime node.
60. **Resolve local bindings to lexical slots** — **Benefit: very high function-call performance; effort: high.** Replace per-call `HashMap Identifier Value` environments with compact frame arrays and slot indices.
61. **Use one callable table keyed by resolved call IDs** — **Benefit: high; effort: medium-to-high after Core exists.** Avoid probing separate function, primitive, selector, constructor, and type-constructor maps for every candidate.
62. **Compile primitives to opcodes/direct implementation indices** — **Benefit: high; effort: medium-to-high after Core exists.** Remove name/signature dispatch and fallback `App` construction from normal primitive calls.
63. **Compile patterns into runtime decision trees** — **Benefit: high; effort: high.** Replace repeated clause walking and binding-list construction with tag dispatch and precomputed binding slots.
64. **Give runtime constructors numeric tags and compact argument arrays** — **Benefit: high; effort: high.** Make constructor tests and selectors constant-time array operations.
65. **Make sets and maps persistent runtime values with structural keys** — **Benefit: very high for collection workloads; effort: high.** Eliminate `T.pack . show . normalizeSetValue`, duplicate key structures, and reconstruction on every primitive operation.
66. **Replace linear ordered-map key lists** — **Benefit: high for maps; effort: medium after `Value`.** Remove `mapKeys ++ [key]`, `elem`, filtering, and repeated `Map.fromList` conversions while preserving observable ordering deliberately.
67. **Introduce a compact list runtime representation** — **Benefit: high for list-heavy programs; effort: high.** Avoid representing every cons cell as `App (Var ...) [head, tail]` with repeated candidate inspection.
68. **Use `SmallArray`/vectors for arguments, fields, and frames** — **Benefit: medium-to-high; effort: medium after `Value`.** Sizes are usually known and small, making lists and repeated zips unnecessarily allocation-heavy.
69. **Add a small-integer representation with `Integer` fallback** — **Benefit: medium-to-high numeric workloads; effort: medium-to-high after `Value`.** Keep arbitrary precision semantically while avoiding a heap object for common integers.
70. **Specialize hot primitives and selectors** — **Benefit: medium-to-high; effort: medium after Core/`Value`.** Lower numeric, string, list, comparison, and record operations directly.
71. **Replace the hot evaluator transformer stack if profiling still warrants it** — **Benefit: medium; effort: medium-to-high.** A strict custom evaluator result can remove `StateT`/`ExceptT` overhead after larger allocation sources are gone.
72. **Add Core-level constant folding, dead-binding removal, and selective inlining** — **Benefit: high across interpreter and JS; effort: high.** Optimize once before either backend rather than duplicating local optimizations.
73. **Make the LSP use incremental text synchronization and a rope/piece table** — **Benefit: high for large documents; effort: high.** Update only edited text and affected line offsets rather than rebuilding complete `Text`, line vectors, and line-start vectors.
74. **Replace LSP containment scans with an interval or per-line index** — **Benefit: high for large documents; effort: medium-to-high.** Current position queries filter and sort every indexed span, despite comments describing them as near-O(log n).
75. **Incrementally parse/typecheck top-level LSP declarations** — **Benefit: very high editor latency; effort: very high.** Reuse the unchanged prefix and unaffected declaration results after an edit.
76. **Store shared base parser/typechecker state plus per-document overlays** — **Benefit: high LSP memory; effort: high.** Avoid duplicating the entire prelude state in every open document.
77. **Precompute and cache hover information by node ID/version** — **Benefit: medium-to-high LSP; effort: medium.** Avoid rerunning `inferType` and repeated morphology/type rendering during hover.
78. **Build a symbol-to-use-ranges index for highlights/references** — **Benefit: medium-to-high LSP; effort: medium.** Replace repeated closure construction and AST walks with direct indexed lookup.
79. **Cache completion candidates and items per document version** — **Benefit: medium LSP; effort: low-to-medium.** Perform only prefix filtering and ranking at request time.
80. **Update the workspace index from watched-file notifications** — **Benefit: medium LSP; effort: medium.** Incrementally add/remove/reload one file rather than rescanning roots; the current watched-files handler is empty.
81. **Normalize URI keys before inserting them into LSP maps** — **Benefit: low; effort: very low.** Remove linear fallback scans that normalize and compare every stored URI.
82. **Preserve render/token cache entries across compatible document versions** — **Benefit: medium LSP; effort: medium.** Reuse entries whose node/type identity survives an edit instead of discarding both tables wholesale.
83. **Bound long-lived LSP morphology, rendering, and document caches** — **Benefit: medium memory/stability; effort: medium.** Use LRUs or explicit size policies for server sessions that remain open for days.
84. **Use explicit managed FST initialization and lifetime** — **Benefit: low-to-medium reliability/memory; effort: low-to-medium.** Replace `unsafeInterleaveIO`, free the input `CString`, and attach finalizers to long-lived FST objects.
85. **Flatten the C/Haskell Foma result ABI** — **Benefit: high morphology throughput; effort: medium-to-high.** Return one UTF-8 buffer plus row/string offsets instead of nested `calloc`/`strdup` arrays and repeated pointer peeking/freeing.
86. **Use a small apply-handle pool for concurrent LSP morphology** — **Benefit: medium after asynchronous analysis; effort: medium.** Preserve handle safety without serializing every morphology call through one long-held lock.
87. **Bound the global possessive-normalization cache** — **Benefit: low memory; effort: low.** Use a hash map with an LRU/size cap rather than an unbounded ordered map for a long-running server.
88. **Precompute frequently rendered prelude names and signatures** — **Benefit: low-to-medium startup/REPL/LSP; effort: low-to-medium.** Store stable rendered forms in the prelude image or shared render cache.
89. **Delay detailed diagnostic rendering until the selected error is emitted** — **Benefit: medium on failure-heavy workloads; effort: medium.** Keep structured errors cheap and avoid Foma/type rendering for discarded alternatives.
90. **Use native structural collection representations in generated JavaScript** — **Benefit: high for JS collection workloads; effort: high.** Replace textual key canonicalization with stable structural hashes/IDs and purpose-built persistent operations.
91. **Specialize generated list code to arrays where semantics permit** — **Benefit: high for JS list workloads; effort: high.** Retain persistent cons representation only where sharing or pattern behavior requires it.
92. **Incrementally cache generated Core/JS per module** — **Benefit: high repeated codegen; effort: high.** Recompile and rerender only modules whose source, dependencies, or relevant compiler options changed.
93. **Prewarm caches serially before parallel tests** — **Benefit: medium CI stability/time; effort: low-to-medium.** Make the parallel test phase read-only to avoid redundant work and cache-write races.
94. **Expose an in-process test runner API** — **Benefit: very high test throughput; effort: high.** Reuse one FST and prelude state across cases while isolating evaluator state and per-test environment.
95. **Add a structured batch test command** — **Benefit: very high test throughput; effort: high.** Thread explicit environment overrides and return per-file parse/type/eval results instead of calling fail-fast `die`.
96. **Reduce routine JS differential process count** — **Benefit: high test throughput; effort: medium.** Use checked-in output goldens for most runs and reserve native-vs-JS comparison for codegen-focused or scheduled suites.
97. **Reuse a persistent isolated Node worker for JS tests** — **Benefit: medium-to-high test throughput; effort: medium-to-high.** Execute generated modules in resettable VM contexts instead of starting Node for every file.
98. **Add explicit CI sharding** — **Benefit: medium wall-clock CI; effort: low-to-medium.** Partition native, failure, REPL, JS, and LSP cases predictably across runners.
99. **Provide separate development and release optimization profiles** — **Benefit: high developer build time; effort: low.** Use `-O0`/`-O1` for iteration and retain `-O2` for release and performance CI.
100. **Split embedded JavaScript runtime data from native runtime modules** — **Benefit: medium binary size/rebuild/startup; effort: medium.** Avoid pulling large JS strings and codegen-only logic into execution modes that never generate JavaScript.
101. **Consolidate duplicated runner orchestration in `Kip.Runner` and `app/Main.hs`** — **Benefit: medium build size/time and future optimization reach; effort: high.** One engine prevents fixes from being implemented twice or diverging.
102. **Choose workload-specific RTS defaults** — **Benefit: medium; effort: medium.** Short CLI/tests, batch builds, REPL, playground, and LSP should be benchmarked independently instead of sharing broad `-N`/allocation-area assumptions.
103. **Add a long-lived compiler worker/daemon** — **Benefit: very high repeated-command startup; effort: very high.** Reuse decoded prelude/Core, identifiers, FST handles, and workspace caches across CLI invocations.
104. **Implement a flat bytecode VM** — **Benefit: potentially very high interpreter throughput; effort: very high.** Replace AST walking with compact instructions, constant/symbol pools, numeric tags, stack frames, and direct call targets.
105. **Typecheck independent module SCCs in parallel** — **Benefit: high on large projects; effort: very high.** Schedule modules once dependency interfaces are available while preserving deterministic declaration/diagnostic order.
106. **Experiment with cache compression only after cache-v2 deduplication** — **Benefit: uncertain-to-medium; effort: medium.** Benchmark LZ4 or low-level Zstandard after duplicate state and strings are removed; otherwise compression merely masks the layout problem.
107. **Investigate Foma-native approximate lookup or a smaller specialized FST** — **Benefit: uncertain-to-high diagnostics/startup; effort: high.** Proceed only if suggestion ranking and accepted-language behavior can remain identical.
